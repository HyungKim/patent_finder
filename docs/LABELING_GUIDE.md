# 라벨 가이드 v1.0

검토자가 YES / NO / HOLD를 같은 기준으로 주기 위한 문서다. 기준을 바꾸면 버전을 올리고 `review.label_guideline_version` 을 함께 바꾼다.

## 무엇을 판단하는가

"이 구간에 특허 담당자가 검토해 볼 기술 내용이 있는가"만 판단한다. 등록 가능성, 신규성·진보성, 침해 여부는 판단하지 않는다. 기술 내용이 있다고 해서 새롭다는 뜻은 아니다.

| 라벨 | 기준 | 학습 사용 |
|---|---|---|
| YES | 구체적인 구성, 제어, 처리 방법이 적혀 있다 | 양성 |
| NO | 일정, 행정, 단순 목표, 수단 없는 성과 소개 | 음성 |
| HOLD | 문맥이 부족하거나 전문 검토가 필요하거나 판단이 갈린다 | 제외 |

## YES로 보는 내용

- 조건과 동작: "Radar confidence가 임계값보다 낮으면 camera feature의 가중치를 증가시키고, 신뢰도가 회복되면 이전 가중치로 복귀한다."
- 구체적인 구성·배치: "냉각 채널을 셀 사이에 배치하고 채널 폭을 입구에서 출구로 갈수록 좁힌다."
- 처리 순서나 알고리즘: "저해상도에서 후보 영역을 찾고 후보만 원본 해상도로 잘라 2차 분류기에 넣는다."
- 수치 조건이나 계산식이 있는 제어·보정 방법.

문제, 해결수단, 효과가 한 구간에 다 있을 필요는 없다. 수단만 있어도 YES다.

## NO로 보는 내용

- 일정·예산·인력·회의: "다음 분기에 센서 융합 성능 개선을 추진한다."
- 수단 없는 목표나 성과: "오검출이 기존 대비 12% 감소", "정확도 95% 달성".
- 시장·배경 설명, 제목, 목차, 표 머리행, 인사말.
- "기존 방식 유지", "변경 없음".

## HOLD로 두는 경우

- "기존 방법을 개선하였다."처럼 주변을 봐야 내용을 알 수 있는 문장.
- 해당 분야 담당자의 확인이 필요한 내용.
- 판단이 서지 않으면 YES/NO를 억지로 고르지 말고 HOLD를 준다.

## 꼭 지킬 규칙

1. **라벨은 대상 구간에만 붙인다.** 주변 문단에 후보가 있다는 이유로 대상 구간을 YES로 하지 않는다.
2. 여러 구간으로 나뉜 긴 문단은 후보 내용이 있는 구간만 YES로 한다.
3. 표 행은 행 전체를 보고 판단한다. 처리 방식이 적힌 셀이 있으면 YES다.
4. 파서가 글자를 잘못 읽었거나 구간이 어긋나 있으면 사유에 `파싱 오류` 또는 `구간 오류`를 체크한다. 그 구간은 학습에서 빠진다.
5. 이미지나 도식 안에만 있어서 화면에 나오지 않은 후보는 "파싱 누락 후보 등록"으로 남긴다.

## 페이지 검토

슬라이드나 쪽 단위로 한 번에 검토한다.

1. 후보인 구간만 체크한다. 화면은 미리 체크해 두지 않는다.
2. 판단이 안 서는 구간은 `보류`를 누른다.
3. "검토 완료"를 누르면 체크한 구간은 YES, 보류는 HOLD, 나머지는 NO로 기록된다. 이 NO는 '일괄' 표시가 붙어 따로 구분된다.
4. 체크하지 않은 시스템 후보가 있으면 완료 전에 건수가 표시된다. 의도한 것인지 확인한다.

페이지의 모든 구간을 읽고 완료해야 한다. 읽지 않은 페이지를 완료하면 잘못된 NO가 학습에 들어간다.

## 판정 단위가 세분(fine)일 때

설정 `segmentation.unit: fine` 인 폴더에서는 구간이 불릿 하나, 문장 하나, 표의 셀 하나다. 기준은 같고, 다음만 다르다.

- 표는 셀마다 판단한다. 처리 방식이 적힌 셀만 YES이고, 행 제목("제안 1")·비고("신규")·수치만 있는 셀은 NO다. 위 3번 규칙 대신 이 규칙을 쓴다.
- 상위 불릿("제안: 2단계 보정")과 하위 불릿은 각각 판단한다. 방법이 적힌 쪽만 YES다. 상위 줄이 제목 구실만 하면 NO다.
- 조건과 동작이 두 문장에 나뉘어 있으면 동작이 적힌 문장을 YES로 하고, 조건만 적힌 문장은 보류나 NO로 둔다.
- 조각이 짧아 뜻을 알기 어려우면 화면의 제목·앞뒤 문맥을 참고하되, 라벨은 그 조각의 내용에만 붙인다.

## 사유 코드

| 코드 | 화면 표시 | 쓰는 경우 |
|---|---|---|
| CONCRETE_METHOD | 구체적 방법 | YES의 근거 |
| GOAL_ONLY | 목표만 | 수단 없는 목표·성과 |
| ADMIN_CONTENT | 행정 내용 | 일정·예산·회의 |
| INSUFFICIENT_CONTEXT | 문맥 부족 | HOLD 사유 |
| PARSING_ERROR | 파싱 오류 | 글자·순서가 잘못 추출됨 (학습 제외) |
| WRONG_SPAN | 구간 오류 | 구간 경계가 어긋남 (학습 제외) |
| DOMAIN_REVIEW_NEEDED | 전문 검토 필요 | HOLD 사유 |
| OTHER | 기타 | 메모에 내용을 적는다 |

## 검토자가 여럿일 때

같은 구간에 검토자들의 판정이 다르면 자동으로 HOLD(합의 대기)가 되고 학습에서 빠진다. 나중에 판정한 사람이 이기지 않는다. 합의한 뒤 한쪽이 판정을 고치면 풀린다.
