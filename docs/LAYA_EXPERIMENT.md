# Laya 2단계 판단 실험

상태: **실험용**. 기본 설치와 Windows 설치 묶음에는 들어 있지 않다. 2026-10-05에 개발용 Mac에서 합성 자료로만 돌려 봤다.

1차 판정(E5 + 분류기)이 후보로 올린 문장을 `convaiinnovations/laya-multilingual` 에 다시 물어 보고, 두 판단을 나란히 비교한다. 스펙 8.2의 shadow 방식이다. 1차 판정과 기존 결과물은 바꾸지 않는다.

## 결론부터

합성 사업부 보고자료 6개(구간 1,006개, 1차 후보 222개)에서 잰 결과다.

- Laya로 후보를 걸러내면 헛표시가 줄지만 **진짜 후보도 함께 잃는다.** 어느 기준에서도 스펙 8.3의 조건(Recall 하락 1%p 이하, Recall 0.95 유지)을 채우지 못했다.
- 걸러내는 용도(`filter`)로는 지금 쓸 수 없다. 사람이 판정한 사내 문서가 쌓이면 그 자료로 다시 재 볼 수 있다.
- 판정이 쌓인다고 Laya가 나아지는 것은 아니다. 판정으로 다시 학습하는 것은 1차 분류기뿐이다 (아래 "판정이 쌓이면 나아지는가").
- 이 수치는 합성 자료에 대한 것이며 실제 문서에서의 성능을 뜻하지 않는다. 질문과 '동의' 기준은 사람 라벨로 검증하지 않았다.

> 2026-10-05 수정: 처음 적은 표는 헛표시를 실제보다 많게 셌다(PPTX 37, PDF 48). 대조 도구가 블록 이름 같은 짧은 항목을 그 낱말이 들어간 다른 후보 문장에도 짝지었기 때문이다. 도구를 고친 뒤의 값으로 바꿨다. 잃은 진짜 후보의 수와 Recall은 그대로다. 블록 이름에 관한 설명도 아래처럼 고쳤다.

### 어떤 문장에서 효과가 있었나 (기준 0.5)

| 1차 후보의 종류 | PPTX | PDF |
|---|---|---|
| 헛표시: 방법 없이 문제(배경)나 결과 수치만 적은 불릿 | 16개 중 12개 걸러냄 | 16개 중 12개 걸러냄 |
| 헛표시: 슬라이드 제목 | 8개 중 4개 걸러냄 | 8개 중 4개 걸러냄 |
| 헛표시: 블록도 안의 짧은 블록 이름 | 1개 중 1개 걸러냄 | 17개 중 2개 걸러냄 |
| 헛표시: 표 행 | 2개 중 0개 걸러냄 | 2개 중 0개 걸러냄 |
| 헛표시: 차트 제목 | 1개 중 1개 걸러냄 | 1개 중 1개 걸러냄 |
| 진짜 후보: 불릿 문장 | 81개 중 9개 잃음 | 78개 중 8개 잃음 |
| 진짜 후보: 표 행 | 21개 중 1개 잃음 | 21개 중 1개 잃음 |
| 진짜 후보: 블록도 아래의 설명 문장 | 8개 중 0개 잃음 | 8개 중 0개 잃음 |

- 문제나 결과만 적은 문장은 잘 걸러냈다. 예: "차체 가림으로 한쪽 안테나 수신 품질이 급격히 떨어짐" (Laya 점수 0.00).
- 블록 이름이 헛표시가 되는 것은 거의 PDF에서다. PDF에서는 블록 이름들이 한 줄로 합쳐져 한 구간이 되고 그 구간이 후보가 된다. Laya는 이런 줄을 거의 걸러내지 못했고 높은 점수를 줬다. 예: "온도 추정기 홀 센서 보정 코일 구동기" (Laya 점수 0.96). PPTX에서는 블록 이름이 따로 추출되어 후보가 된 것이 1개뿐이었다.
- 잃은 진짜 후보는 조건과 수치가 뚜렷한 제어 문장이었다. 예: "모듈 온도가 95도를 넘으면 송신 전력을 1 dB씩 단계적으로 낮추고 90도 이하로 3초 유지되면 한 단계씩 복귀한다" (Laya 점수 0.23).
- 1차 후보 안에서 진짜와 헛표시를 가르는 정도(AUC)는 Laya 0.86 / 1차 점수 0.96 (PPTX), Laya 0.78 / 1차 점수 0.95 (PDF)이다. 후보 안에서도 1차 점수가 Laya 점수보다 잘 가른다.

### 판정이 쌓이면 나아지는가

- Laya는 이 프로그램의 재학습 대상이 아니다. 판정이 쌓여도 Laya의 답은 바뀌지 않는다.
- 판정이 있으면 동의 기준을 고르고 점수를 보정할 수 있다. 그러나 합성 자료에서는 결과를 보고 가장 유리하게 기준을 골라도 부족했다. 진짜 후보를 1개(Recall 약 1%p)만 잃는 선에서 걸러지는 헛표시는 다음과 같다.

| 무엇으로 거르나 | PPTX (헛표시 28개) | PDF (헛표시 44개) |
|---|---|---|
| 1차 점수의 기준만 올림 (Laya 없이) | 11개 | 16개 |
| Laya 점수 | 5개 | 5개 |
| 두 점수를 합침 (문서 2개로 가중치를 정해 나머지 1개에 적용) | 8개 | 12개 |

- Laya를 쓰는 것보다 1차 점수의 기준을 올리는 쪽이 더 많이 걸러냈다. 두 점수를 합쳐도 1차 점수만 쓴 것보다 못했다. 점수 보정은 점수의 순서를 바꾸지 않으므로 이 결과를 바꾸지 못한다.
- 두 점수의 순위 상관은 0.37~0.38로 낮다. Laya가 1차와 다른 것을 보기는 하지만, 그 차이가 진짜와 헛표시를 가르는 데 보탬이 되지 않았다.
- 모델 설명서는 특정 업무에서 재학습 없이 쓴 성능이 우연 수준에 가깝고, 그 업무에 맞춘 재학습(fine-tuning)에서 능력이 나온다고 적고 있다. 한국어 정확도는 0.49로 적혀 있다. 설치한 SDK(0.3.27)에는 점수 보정 기능이 있고 재학습 기능은 찾지 못했다. Laya를 판정 자료로 재학습하는 일은 해 보지 않았다.
- 문장 종류별 결과, AUC, 위 표는 일회성 집계로 냈고 저장소의 도구로는 다시 만들 수 없다. 기준별 표는 `tools/check_expected.py --laya` 로 다시 만들 수 있다.

## 무엇을 하고 무엇을 하지 않는가

`laya-compare --run <run>` 은 저장된 run 하나를 읽어 다음을 한다.

- 1차가 후보로 본 구간 **전부**를 Laya에 묻는다. 대상 문장과 그 문단의 제목(슬라이드 제목)을 함께 준다.
- 질문은 하나다: "대상 문장에 구체적인 구성, 처리 순서, 제어 방법 또는 수치 조건이 적혀 있는가?" (예/아니오, 질문 버전 `laya-q1`). 답은 '예'일 확률(0~1)로 나온다. 보정하지 않은 값이다.
- 점수가 동의 기준(기본 0.5) 이상이면 '동의', 미만이면 '이견'으로 적는다.

바꾸지 않는 것:

- 1차 판정, `report.html`, `results.jsonl`, `marked/` 의 마킹 사본, 원본 문서.
- 분석(`analyze`, `mark`), 내보내기(`export`), 검토 화면은 2단계 결과를 읽지 않는다. `laya.mode` 는 여전히 `off` 만 허용한다.

만드는 것 (`outputs/<run>/laya/`):

| 파일 | 내용 |
|---|---|
| `laya_report.html` | 후보마다 1차 점수, Laya 점수, 동의·이견. Laya 점수가 낮은 순서. 이견은 붉은 줄 |
| `laya_results.jsonl` | 같은 내용을 한 줄에 한 후보씩 |
| `laya_summary.json` | 건수, 걸린 시간, 모델·질문 버전, 동의 기준 |
| `marked_laya_agree/` | Laya가 '이견'을 낸 후보의 표시를 뺀 PPTX·PDF 사본 (비교용) |

- 판단에 실패한 후보와 사람이 YES로 판정한 구간은 비교용 사본에서도 빼지 않는다 (스펙 8.3).
- 결과는 DB의 `second_stage_results` 에 같은 1차 prediction ID로 덧붙인다. 표본 선택 방식(`stage1_candidates_all`), 포함 확률(1.0), 동의 기준을 함께 적는다. 같은 run을 다시 돌리면 같은 행을 새 결과로 바꾼다.

## 준비 (인터넷이 되는 준비 PC에서 한 번)

Laya SDK는 PyTorch와 transformers가 필요하다. 기본 실행 환경은 이 패키지들을 일부러 두지 않으므로 환경을 따로 만든다.

```bash
uv venv --python 3.11 .venv-laya
```

```bash
uv pip install --python .venv-laya/bin/python -r requirements/base.in -r requirements/laya.in
```

```bash
python3 tools/fetch_laya_model.py --dest models/laya-multilingual
```

- 디스크: 설치한 실험 환경 942MB, 모델 658MB (이 Mac에서 잰 값).
- 시험까지 돌리려면 `requirements/dev.in` 의 pytest도 이 환경에 설치한다.
- 모델은 고정 revision `1720e3e3357cfe1e281542e223f8273b0890ca34` 에서 받고, 파일마다 Hub가 알려 준 해시와 대조한 뒤 `manifest.json` 을 만든다.
- `.venv-laya/` 와 `models/` 는 Git에 넣지 않는다.

## 실행

먼저 평소처럼 분석해서 run을 만든다. 기본 환경(`.venv`)으로 만든 run도 그대로 쓸 수 있다.

```bash
PYTHONPATH=src .venv-laya/bin/python -m patent_marker.cli mark tests/fixtures/divisions
```

출력 마지막에 나오는 run 이름(`mark-날짜-시각`)을 넣어 비교한다.

```bash
PYTHONPATH=src .venv-laya/bin/python -m patent_marker.cli laya-compare --run mark-20261005-185036
```

- `--agree-at 0.3` 처럼 동의 기준을 바꿀 수 있다 (0~1).
- `--output 폴더` 로 비교 자료 위치를 바꿀 수 있다.
- 기본 환경의 Python으로 실행하면 "Laya 실험 환경이 아닙니다"라는 오류를 내고 끝난다. 모델 폴더가 없거나 해시가 다르면 내려받지 않고 오류를 낸다.

합성 자료는 정답표가 있으므로 표로 대조할 수 있다. 동의 기준을 바꿔 가며 다시 돌릴 필요 없이 여러 기준의 결과를 한 번에 보여 준다.

```bash
.venv/bin/python tools/check_expected.py --results outputs/mark-20261005-185036/results.jsonl --laya outputs/mark-20261005-185036/laya/laya_results.jsonl
```

## 모델을 불러오는 방식

- 스펙 8.1대로 승인한 checkpoint 하나만 로컬 폴더에서 불러온다. SDK의 자동 Router(여러 모델 선로딩)는 쓰지 않는다.
- 불러오기 전에 `manifest.json` 의 모든 파일 해시를 확인한다. 하나라도 없거나 다르면 중단한다.
- SDK는 불러올 때 `tokenizer/tokenizer_config.json` 을 고쳐 쓴다. 확인된 모델 폴더가 바뀌지 않도록 작업용 사본(`data/laya_runtime/<revision>/`)을 만들어 거기서 불러온다. 설정 파일은 매번 원본에서 다시 복사하고, 가중치는 하드 링크로 둔다(링크가 안 되는 디스크에서는 복사).
- 장치는 `cpu` 로 고정한다. `runtime.offline: true` 이면 다른 명령과 같이 네트워크 가드를 설치한다.

## 한계

- 합성 자료 한 벌로만 쟀다. 사내 문서, 사람이 판정한 라벨로는 재 보지 않았다.
- 스펙 8.1의 질문 네 개 중 하나("구체적인 구성·처리·제어 방법이 있는가")만 쓴다. 질문을 여러 개 함께 물으면 같은 질문의 답이 달라지는 것을 확인해서 하나씩 묻는 방식으로 정했다.
- Laya는 1차 후보만 다시 본다. 1차가 놓친 후보는 찾지 못하고, Laya가 1차보다 나은지도 후보 밖에서는 알 수 없다 (스펙 8.2).
- 동의 기준과 점수 보정은 검증하지 않았다. `calibration_version` 에 `none` 으로 적는다.
- 시간 제한(`laya.timeout_seconds`)은 적용하지 않는다. 판단 오류는 `error` 로 기록한다.
- 실험 환경에는 `huggingface-hub`, `httpx` 처럼 내려받기 기능이 있는 패키지가 함께 설치된다. 기본 설치에는 없는 패키지들이다. 로컬 폴더에서만 불러오고 네트워크 가드를 켠 상태에서 접속 시도가 0건인 것을 시험으로 확인했지만, 운영 PC에 들이려면 따로 검토해야 한다.
- 실험 환경의 패키지는 버전만 고정했고, 해시를 고정한 잠금 파일과 Windows용 wheel 묶음은 만들지 않았다. 회사 PC에서 돌리려면 그 작업이 먼저 필요하고, PyTorch 때문에 설치 묶음이 크게 늘어난다.
- `assist`(2차 판단을 검토 화면에 함께 보여 주기)와 `filter` 는 구현하지 않았다.

- `requires_laya` 표시가 있는 시험 1개는 실제 모델을 불러온다. `.venv-laya` 에서만 실행된다.

```bash
.venv-laya/bin/python -m pytest tests/integration/test_laya_compare.py -q
```
